# M3 内存规则

规则页可查看一个有效内存规则集、编辑完整 YAML、校验、回放本次会话的真实历史、提出修改、审批和回滚。
沿用粉色主题及 Desktop Acrylic。没有修剪、结束进程、脚本、命令执行或提权实现。

## 格式与边界

正式格式为 [默认 YAML](../src/SysBox.Rules/default.yaml) 和 [JSON Schema](../src/SysBox.Rules/memory-rules.schema.json)。
schema_version=1。基于 YamlDotNet 18.1.0 的低层事件流先检查安全限制，再构造 JSON 树执行 Schema 子集及语义校验；
不把 YAML 反序列化为用户指定的运行时类型。校验器只实现本项目 Schema 使用的关键字，不是通用 JSON Schema 产品。

- 输入最多 64 KiB UTF-8、深度 12、4096 个解析事件、单文档。锚点、别名、所有显式标签、重复及未知字段均拒绝。
- 必填、类型、枚举、数值、数组长度及字符串格式按 Schema 检查。错误给出 code/path；语法错误提供行列。
- 条件必须且只能使用 all 或 any；最多 32 个比较条件。百分比 0–100，支持 lt/lte/gt/gte。
- 采样间隔 2–60 秒，历史 1–30 分钟，持续时间至少一个采样周期且须被历史窗口覆盖。
- 冷却 1–86400 秒，每小时最多 1–60 批通知。一次触发可产生多条 notify 消息，次数限制按批计数。
- 前台/系统保护、用户进程限定和交互审批不能关闭，进程年龄至少 120 秒，修剪候选目标上限为 2。
- 进程保护名单最多 64 个基本 .exe 名称，不允许路径、通配符和命令。它们被校验并保存在版本中。
- notify 是低风险可启用动作，level/message 必填；trim_working_set 是危险动作，只能 enabled:false 并提供 selector。
  未知动作或启用修剪直接拒绝。当前执行策略在选择目标前排除全部修剪，因此不会伪造某进程被具体过滤器排除的结果。
- default_dry_run=true、audit_enabled=true、include_raw_paths_in_logs=false 是固定安全约束。

Schema 的安全限制和语义限制共同生效；不是只读取格式中的部分字段后声称危险动作可用。
所有模拟输出都标注 dry-run、实际执行 0、释放量未知。通知报告保留等级和消息；不估算所谓可释放内存。

## 计算、历史和通知

RuleEngine 只产生决定和通知描述，没有任何清理执行器。RuleSimulator 对给定的 RuleSample 序列确定性回放，
每个条件分别计算持续时间，all 要求全部持续达标，any 要求其中一个持续达标。
比较使用真实物理可用百分比和真实系统提交百分比；提交量缺失时该条件不满足。
持续时间由 Stopwatch 单调时间计算，UTC 仅用于显示；重复/倒退的单调时间被拒绝，超过两倍采样周期的间断重新计时。

应用窗口存活期间，RuleObserver 根据有效规则的采样间隔只读采集系统内存，和 M2 内存页的进程表循环独立。
历史只在内存中保留，最长 30 分钟且最多 1024 点；不保存进程名、路径或内存正文。关闭窗口停止观察。
规则禁用时不会通知；采集失败显示错误，缺失时间不补假数据。
实际通知在规则页显示，不发送系统 Toast、邮件或网络消息。最后一次通知保留时间标记。

实时通知先提交有界审计，再显示消息。全局冷却和小时频率还会检查已持久化的通知审计，避免重启或更换规则版本绕过限制；
墙钟倒退时保守抑制通知。规则版本变化会重新观察持续时间。
模拟从给定历史的干净状态回放，不读写实时冷却；实时通知可能额外受到已保存的全局冷却限制。
重启不会恢复原会话历史，须重新积累持续时间。

## 草案、审批和版本

IRuleService 仅提供 validate/simulate/read/propose。应用注入 RuleDraftService facade，不能将它转为审批接口。
IRuleReview 只交给 WinUI 组合根/规则页，不向 Agent 服务暴露；未实现 CLI、MCP 或远程审批。
这属于同进程的能力划分，不是防御本地任意代码、同用户文件篡改或界面自动化的身份认证机制。
未来 IPC 仍需独立验证调用方；审批不会凭 Agent 提供的 Boolean 或自生成确认码通过。

提案保存不可变 YAML、SHA-256、基准 revision/hash、原因和模拟报告，15 分钟到期。
草案 revision 必须等于当前基准；提出及批准时均比较版本和哈希，冲突返回 CONFLICT_REVISION。
审批对话框显示完整旧/新配置、原因、哈希、模拟通知数和到期时间；默认按钮为取消。
取消只关闭对话框，草案保持待审直到到期；拒绝记录审计，批准才产生新有效版本。
批准前重新校验原提案；之后编辑框的改动不会替换已显示/保存的提案。

回滚先生成历史内容的提案，再经相同审批生成递增版本，例如 v2 → 恢复 v1 内容 → v3。
只修改根 revision 标量，保留 YAML 注释和排版；revision 不会倒退，避免旧提案重新匹配。
有效版本、快照、提案及审批事件在一个原子事务中提交，不先写有效配置再补审计。

## 存储

默认 `%LOCALAPPDATA%\SysBox\rule-state.json`，只属于当前用户。
与手册目标中的单独 memory-rules.yaml 不同，M3 将完整 YAML 放在此事务信封的 Active.Yaml 中，
使有效配置、版本和审批审计能够一起替换；没有第二个可编辑且会绕过审批的有效配置文件。
初次启动从嵌入的默认 YAML 初始化；编辑入口是规则页。

跨实例写入使用独占锁文件；锁冲突返回 STORE_IO，可重试，不静默覆盖。
同目录临时文件刷新后原子替换，保留上一份 .bak。最多保留 100 个版本、100 个提案和 500 个审计事件，
最多 20 个未过期待审提案；总存储上限 32 MiB。旧版本超出保留窗口后不再出现在回滚列表。
损坏、哈希不符或无权访问均停用观察并显示错误，保留文件，不自动覆盖成默认值，也不自动信任备份。
当前审计为本地有界记录，不是防篡改账本，不提供自动长期归档。

仅 Debug 允许 SYSBOX_TEST_RULE_DIRECTORY 重定向测试存储；Release 不编译此覆盖路径。
scripts/rules-smoke.ps1 的审批只操作仓库 artifacts 下的隔离规则，不修改用户的有效策略。
