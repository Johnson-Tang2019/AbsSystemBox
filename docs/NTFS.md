# NTFS 增量索引与可选只读服务

2026-11-02，开发版本 0.2.0-preview.1。这是已接入应用的代码实现说明，不是真实卷验收报告。用户继续暂缓隔离卷创建、格式化、整卷枚举和真实 USN 变更对账；未把这些项目记为通过。

## 使用与授权

普通目录扫描保持默认。设置页的粉色卡片提供服务状态、卷根目录、建立/重建、停止和恢复跟踪。初始卷选择为空；安装服务不会开始扫描。

完整安装包携带 `app/scripts/install-ntfs-service.ps1` 和 `app/ntfs-service`。在设置页填写盘符根目录后启动独立安装工具；工具要求管理员身份，并显示默认“否”的确认，列明用户 SID、调用程序、卷 GUID 和整卷元数据范围。即使 UI 运行账户是管理员，也需要此确认。不要从 Agent 自动点击授权。

服务会允许获准用户读取获准整卷的文件名、目录结构、大小和硬链接，可能包含其他账户目录。它不读取文件正文，不删除文件，不提供任意命令或任意 DeviceIoControl。UI/CoreHost 始终使用普通用户身份；服务不可用时，搜索页的普通目录模式仍可使用。

单独在设置页确认“建立 / 重建整卷索引”才开始读取；最多一百万个身份/目录项，初始构建三十分钟合作预算。只有盘符根目录可开启高速模式，不接受设备路径或 UNC 路径。停止保留快照；恢复只续接已有日志，不自动全卷重扫。离开建立任务页面会取消未完成的建立任务；已经完成的增量跟踪随活动桌面租约运行，完全退出停止。

## 组成与一致性

- `SysBox.NtfsService` 是独立 Windows Service，账户 LocalSystem，固定服务名 `AbsSystemBox.Ntfs`，固定受保护路径 `%ProgramFiles%/AbsSystemBox/NtfsService`。
- `SysBox.NtfsBroker` 负责显式管道 ACL、操作/卷授权、OS 调用者身份及 SCM 服务身份验证。服务授权文件为 `%ProgramData%/AbsSystemBox/NtfsService/grants.json`，普通进程不能通过 RPC 修改。
- `WindowsNtfsVolumeReader` 根据规范卷 GUID 打开只读卷句柄；Native 只开放固定 FSCTL。`OpenFileById` 补齐大小、属性、时间及硬链接；全部原生句柄使用 SafeHandle，布局与长度检查失败即拒绝。
- `NtfsLiveIndex` 保存首次 Journal 起点，枚举 MFT 到 SQLite staging，分批补齐当前元数据，再追平初始扫描期间的日志，最后一次原子发布到共享 `metadata.db`。
- 增量批次去重身份后重新读取当前元数据，协调改名、移动、大小变化、硬链接新增/删除以及目录子树路径；缓存、目录项、祖先汇总、快照 revision 和 checkpoint 在同一事务内提交。
- 当前元数据可能比消费的 USN checkpoint 更新；checkpoint 表示已处理的日志下界，重复回放幂等，不假装是文件系统某一瞬间的冻结快照。
- Journal 更换/截断、卷绑定变化要求用户手动重建；事务失败保留上一份共享快照和 checkpoint。临时不可读项保留最后已知元数据，报告 Partial，空闲批次也会重试。达预算上限停止继续跟踪。
- 与普通目录扫描共用单写者和搜索/存储契约。普通目录快照成功覆盖同一范围时，原 NTFS 跟踪状态在同一发布事务内移除，避免其复活旧 generation。

Migration 3 增加独立 `snapshot_revision` 与物理文件身份索引；已有 schema 1/2 在迁移前通过 SQLite online backup 保留 `metadata.schema*-*.backup.db`。迁移使用事务；失败不删除备份。不支持自动降级旧程序读取新 schema。

搜索的 FileId 对 NTFS 项目返回规范实体身份；硬链接的多个名称共享该身份。目录逻辑/分配汇总仍按目录项累计，另外提供按物理身份去重的已知分配量与未知对象数。分配量不等于卷已用空间：系统保留空间、不可读项和重解析点不会伪造成完整统计；Partial 状态中的历史大小可能已过时。

## 安全与资源边界

服务管道 `AbsSystemBox.Ntfs.ReadOnly.v1` 只允许 System 和明确获准 SID，拒绝网络身份。服务从 OS 获取客户端 PID、会话、映像、Token SID，并核对管道模拟身份；授权同时匹配 SID、固定 CoreHost 映像路径和卷 GUID。客户端验证对端 PID 属于 SCM 中运行的固定 LocalSystem 服务、会话 0、固定映像及受保护文件 ACL，避免伪造服务。

固定方法只有 `capabilities`、`journal`、`enumerate`、`changes`、`objects`。UInt64 身份/游标通过十进制或十六进制字符串传递。RPC 帧最多 8 MiB、四个并发连接、十五秒请求期限、连接等待一秒；每批原生输出 64 KiB、元数据最多 16 个身份、单对象最多 1024 个链接/65536 路径字符。

生产卷 FSCTL 使用 overlapped I/O、十五秒等待与 CancelIoEx，取消后等待驱动完成再释放缓冲区；异常存储驱动仍可能延迟完成，不能保证硬实时终止。单文件元数据 API 是同步调用，逐身份检查取消并限制批次/链接数量。初始构建和每次续接都有合作时间预算。后台每五秒检查，桌面租约九十秒内有效时才继续，不因 CLI/MCP 查询自动启动扫描。

Agent 可以读取 `ntfs.status` / `ntfs.capabilities`；`ntfs.build` / `ntfs.resume` / `ntfs.stop` 仅接受由 OS 验证的桌面调用者。`approved`、`isUi`、`administrator` 字段不授予权限。没有公开给 MCP 的高权限工具。

## 服务维护

安装工具先验证负载清单和 SHA-256，在受保护的唯一 incoming 目录复制并再次核验，显式设置文件/目录所有者和 ACL，再停止固定服务、切换目录、提交授权并启动。拒绝降级、未知服务注册、非本产品目录、重解析路径和不可信所有者/写权限。失败尝试恢复旧目录和配置；旧 owned 负载与授权备份保留供管理员回滚，不递归删除未知文件。

应用仍按固定用户级身份覆盖升级。可选服务的更新需要再次运行上述独立管理员工具；应用安装不会悄悄修改 System 服务。卸载若检测到该服务，会等待独立管理员移除工具；取消/失败则中止卸载并保留应用。静默卸载不会代替用户批准服务移除。移除工具只停止并删除固定 SCM 注册，保留服务负载、授权备份、用户配置和索引源文件。

## 本轮证据与限制

新增 Windows 定向测试和真实非管理员设置页流程见 `validation/ntfs-service/`。测试使用 fake 元数据读取器、临时 SQLite 和本机有界命名管道；没有执行真实卷 MFT 枚举。

代码已经接入共享搜索/存储及设置页，但仍未验证：真实 LocalSystem SCM 安装/升级/移除循环、真实隔离 NTFS 卷一致性及长期大卷性能。安装脚本解析和 NSIS 编译只证明对应语法可构建。不得以这些结果声称生产环境全部验收完成。重启、其他系统和干净机器等场景按用户要求不作为本轮验收项。
