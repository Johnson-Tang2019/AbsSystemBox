# 阈值与定期内存清理

2026-11-02 用户新增授权实现此功能，替代早期“不加入内存清理”的范围限制。
默认关闭；YAML 规则仍只通知/模拟，清理采用独立的桌面确认设置。

在内存页选择阈值和/或定期模式，保存并确认。自动清理采用默认保护与可选排除名单，不需要填写白名单。排除名单留空时只使用默认保护。
关闭启用选项并保存会立即阻止后续轮次。已发生的工作集收缩不能撤销，应用会按需重新调入页面。
自动进程清理不结束进程、不删除用户数据，也不清空系统缓存或 Standby List。手动九类系统清理使用单独的管理员确认，详见下方说明。

| 设置 | 默认 | 范围/行为 |
|---|---|---|
| 内存阈值 | 90% | 50–98%，物理内存使用率；已有配置保持原值 |
| 持续时间 | 45 秒 | 10–3600 秒；睡眠/采样中断后重新累计 |
| 定期模式 | 关闭，30 分钟 | 5–1440 分钟；使用率低于 50% 时不处理 |
| 冷却 | 300 秒 | 60–86400 秒；跨重启保存运行前记录 |
| 最小工作集 | 256 MiB | 64–65536 MiB |
| 自定义排除名单 | 空 | 至多 32 个 `.exe` 文件名；留空可以启用，默认保护不可移除 |
| 单轮上限 | 2 项 | 每小时至多 6 轮，不保证每轮找到合格进程 |

仅当前用户、同一会话、未提升权限、启动至少 120 秒的后台进程可进入候选。
系统/安全/桌面/SysBox 进程固定保护；前台窗口在打开目标句柄后再次检查。
使用 PID + 启动时间 + 映像名 + 进程 Token 验证，最小权限句柄调用 `K32EmptyWorkingSet`。
拒绝访问直接跳过，不申请调试权限或管理员权限。

CoreHost 仅在最近 90 秒内存在已验证桌面进程通信时执行自动清理。桌面每 30 秒续期，退出主动停止后台。
CLI/MCP 启动后台只能读取状态，不能启用清理、延续桌面租约或替代确认。
配置写入 `%LOCALAPPDATA%\SysBox\cleanup.json`，原子替换，审计最多 128 条；损坏配置停用并保留原件。
审计不可写时停止实际动作。记录的是进程工作集前后值，不冒充释放的物理 RAM；收缩可能增加缺页和后续调页。

新增验证见 `validation/desktop-agent/README.md`。专用受限权限 fixture 上的实际收缩与早于 120 秒的拒绝已通过；
未对用户日常应用进行清理实验。默认配置与取消确认均保持关闭。
实际调度循环另以受控采样/记录执行器验证租约、触发前落盘和停用后停止读取；不将该测试当作真实硬件压力或真实自动释放 RAM 的证明。

## 0.3 内存页九类清理

清理入口移到内存页。自动清理新配置沿用 Fluent Reduct 的 90%/30 分钟默认值，默认关闭；采用保护与排除名单，保留持续压力、前台/系统/提升权限/跨用户保护、最短年龄与冷却预算。默认保护也包含 Java 游戏进程。旧配置保留已有数值与旧白名单范围；只有在新界面保存并重新确认启用后才切换到保护模式。取消确认不修改配置。

手动系统清理提供全局工作集、逐进程工作集、系统文件缓存、修改文件缓存、修改页面、优先级 0 待机列表、完整待机列表、内存合并、注册表缓存，顺序及默认选择来自已记录的 Fluent Reduct 提交。每次需要独立管理员授权及默认“否”的操作清单确认，不能由配置布尔值或 Agent RPC 自动批准。全局工作集不提供逐进程前台保护；缓存/待机操作可能造成短暂停顿及重新调页。

每项返回真实 NTSTATUS 或逐进程计数；Windows 不支持/拒绝即显示失败，不伪造成功。可用物理内存前后变化包含同期系统活动，不等同于工作集字节差。原生布局/顺序、非 UI 调用者与伪造批准拒绝已定向验证；未在自动测试中实际清空系统缓存/Standby，也未把这些操作记为本机成功验收。

“Fluent Reduct 默认”和“PCL 清理组合”只勾选项目，均不立即执行。PCL 组合参考 PCL-CE 2.10.4 的七项公开操作：全局工作集、修改文件缓存、修改页面、完整/优先级 0 待机列表、内存合并和注册表缓存。继续采用本项目的固定执行顺序、受检原生布局和逐项 NTSTATUS；不复制其历史源码、不依赖 PCL 程序。全局工作集无法遵守逐进程排除名单，界面与每次管理员确认均说明该范围。
