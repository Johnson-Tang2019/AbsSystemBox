# 阈值与定期内存清理

2026-11-02 用户新增授权实现此功能，替代早期“不加入内存清理”的范围限制。
默认关闭；YAML 规则仍只通知/模拟，清理采用独立的桌面确认设置。

在设置 → 内存清理填写明确的进程文件名白名单，选择阈值和/或定期模式，保存并确认。
关闭启用选项并保存会立即阻止后续轮次。已发生的工作集收缩不能撤销，应用会按需重新调入页面。
清理不是结束进程，不删除用户数据，也不清空系统缓存或 Standby List。

| 设置 | 默认 | 范围/行为 |
|---|---|---|
| 内存阈值 | 85% | 50–98%，物理内存使用率 |
| 持续时间 | 45 秒 | 10–3600 秒；睡眠/采样中断后重新累计 |
| 定期模式 | 关闭，30 分钟 | 5–1440 分钟；使用率低于 50% 时不处理 |
| 冷却 | 300 秒 | 60–86400 秒；跨重启保存运行前记录 |
| 最小工作集 | 256 MiB | 64–65536 MiB |
| 白名单 | 空 | 至多 32 个 `.exe` 文件名；空白不能启用 |
| 单轮上限 | 2 项 | 每小时至多 6 轮，不保证每轮找到合格进程 |

仅当前用户、同一会话、未提升权限、启动至少 120 秒的后台进程可进入候选。
系统/安全/桌面/SysBox 进程固定保护；前台窗口在打开目标句柄后再次检查。
使用 PID + 启动时间 + 映像名 + 进程 Token 验证，最小权限句柄调用 `K32EmptyWorkingSet`。
拒绝访问直接跳过，不申请调试权限或管理员权限。

CoreHost 仅在最近 90 秒内存在已验证桌面进程通信时执行自动清理。桌面每 30 秒续期，退出主动停止后台。
CLI/MCP 启动后台只能读取状态，不能启用清理、延续桌面租约或替代确认。
配置写入 `%LOCALAPPDATA%\SysBox\cleanup.json`，原子替换，审计最多 128 条；损坏配置停用并保留原件。
审计不可写时停止实际动作。记录的是进程工作集前后值，不冒充释放的物理 RAM；收缩可能增加缺页和后续调页。

新增验证见 `validation/desktop-agent/README.md`。专用受限权限 fixture 上的实际收缩与早于 120 秒的拒绝已通过；
未对用户日常应用进行清理实验。默认配置与取消确认均保持关闭。
实际调度循环另以受控采样/记录执行器验证租约、触发前落盘和停用后停止读取；不将该测试当作真实硬件压力或真实自动释放 RAM 的证明。
