# 金河田水冷显示

本模块为 GoldenFiled 对应的串口水冷屏独立实现显示控制。0.3.1 包括兼容设备检测、温度与风扇 RPM 来源选择、明确标注的手动显示值、设置保存、手动启动/停止、随应用自动同步和可选持久采集服务。只发送已观察的显示帧，不实现泵速、风扇调速、固件升级或通用设备命令。

## 使用与数据来源

导航中的“水冷显示”页先检测设备与传感器，选择屏幕、温度源及风扇 RPM 源，再开始同步。首次连接预留三秒设备准备时间，之后每秒发送一次。GoldenFiled 必须释放同一串口；程序不自动结束它。0.3.1 由应用单例持有同步任务，切换页面或隐藏到托盘后继续工作；点击“停止同步”或完全退出应用才停止写入并释放连接。

首次设置且尚未保存来源时，只在兼容屏唯一、`Core Max` 温度和 `CPU Fan` RPM 各唯一时自动选择；存在多个同名来源、已保存的来源消失或设备身份改变时要求重新选择，不自动换成其他读数。用户可保存其他实际传感器，稳定标识优先于名称默认值。

“随应用启动同步”默认关闭，勾选并保存后才在应用启动时按已保存的设备和来源检测、启动。Windows 登录时启动应用仍由已有桌面启动设置控制；这两项设置与后台服务随 Windows 启动分别独立。当前用户明确要求开机同步时可同时配置登录启动与随应用同步，不为所有用户或未配置的新安装自动开启显示。

传感器由随应用部署的 `sensors/SysBox.SensorHost` 独立采集，使用 LibreHardwareMonitorLib 0.9.6，不依赖运行 GoldenFiled、HWiNFO 或 LibreHardwareMonitor 桌面程序。显卡可先在普通权限下检测；CPU 与主板风扇需要用户安装、授权可选的受保护采集服务及已有的 PawnIO 驱动。授权安装/更新服务时使用系统提升和默认“否”的原生确认；之后该用户、固定界面映像可通过受限管道读取，不需每次开机重复提升主界面。驱动缺失、权限不足或设备不支持时明确返回不可用。应用不安装 PawnIO 驱动，不把不存在的温度或转速填成零。

自动模式要求所选温度与风扇读数同时存在、数值有效且未过期；缺少任一来源停止同步。风扇仅接受 RPM 读数，百分比不能当作 RPM。手动模式中的数字仅供屏幕显示，与硬件实际状态分开标注；它们不改变风扇或泵速。串口写入成功只表示本机 API 接收了帧，不能代替用户核对物理屏幕。

## 分层与边界

- `Abstractions`：设备、设置、传感器快照与采集/传输端口，以及无依赖的固定五字节帧编码。
- `Core`：设置验证及原子保存；不含 UI 或设备句柄。
- `Native`：仅识别 `USB\VID_1A86&PID_484A&MI_00` 的在线串口，打开前重新检查设备身份；串口使用 SafeFileHandle、检查原生结构大小与五字节写入长度，并设置写入超时。
- `Presentation`：应用单例的有界检测、采集和同步生命周期、读数有效性、取消及迟到结果隔离；页面离开只取消其未完成的检测，不取消既有同步。
- `App`：原生 WinUI 页面及采集客户端；优先连接受保护服务，核验 LocalSystem 服务身份、固定服务映像和保护目录。未安装服务时回退为普通用户显卡采集子进程，随机管道、显式 ACL 和双向映像核验保持有效。没有 Agent 布尔授权入口。
- `SensorHost`：固定的空参数只读采集请求。只启用经授权的 CPU / 主板及显卡组，不启用存储、内存/SPD、网络、外置控制器或电源组，不调用传感器控制接口。普通子进程在父进程退出、管道断开、超时或停止时结束；`--service` 模式由 Windows 管理，界面断开后结束该轮硬件会话，服务本身仍保留安装并等待下一次授权连接。

可选服务名为 `AbsSystemBox.Sensors`，LocalSystem 映像与负载在 `%ProgramFiles%\AbsSystemBox\SensorService`，用户/界面授权在 `%ProgramData%\AbsSystemBox\SensorService`。安装工具验证有界清单、文件摘要、保护 ACL 和固定服务注册，拒绝降级或覆盖未知目录，并保留更新回滚路径。服务只接受被授权用户 SID、普通桌面会话与固定 `SysBox.App.exe` 映像；命名管道拒绝网络主体，调用不能携带控制寄存器、风扇参数或任意命令。服务采集及清理具有时限，安装服务与允许设备同步不由请求中的布尔值授权。

设置在现有用户数据目录的 `cooling-display.json`，采用稳定设备/传感器标识；新增 `AutoStart` 缺失时按 `false` 解释，保留旧设置的默认安全行为。原软件传感器数组下标不导入为 SystemBox 的默认选择。不存在设备或设置损坏时保留可见错误。

## 协议证据与独立编码

| 观察点 | 映像地址 | 静态证据与结论 |
|---|---|---|
| 设备选择 | `0x140001350` | 传入 VID `0x1A86`、PID `0x484A`，后续比较串口设备标识 |
| 串口速率 | `0x140001528` | `setBaudRate` 参数 `0x0F4240`，即 1,000,000；后续设置 8 数据位、无校验、1 停止位、无流控 |
| 明文帧组成 | `0x140003C3A`～`0x140003C78` | 依次追加 `0x74`、`0x00`、温度低字节、风扇转速高字节与低字节，长度五字节 |
| 负载编码 | `0x140003DD1` | 从帧偏移 2 起逐字节 XOR `0x02`，两个头字节保持字面值；与上文五字节组成联合确定三个负载字节的处理 |
| 发送 | `0x14000163F` | 构造后的 QByteArray 进入 QIODevice 写入；不把此调用视为设备回执 |

因此本轮独立实现的线缆数据格式为：

```text
74 00 (temperature XOR 02) ((fanRpm >> 8) XOR 02) ((fanRpm & FF) XOR 02)
```

温度编码范围 0～255，转速范围 0～65535 RPM。例：25 ℃、1000 RPM 的明文负载为 `19 03 E8`，发送帧为 `74 00 1B 01 EA`。边界检查在编码前完成，不允许通过溢出或截断产生任意帧。本轮不添加未观察的亮度、方向、屏幕资源、握手或泵速指令。USB VID/PID 也可能被复用，兼容标识和静态重建不等同于所有同标识固件均已实机验收。
